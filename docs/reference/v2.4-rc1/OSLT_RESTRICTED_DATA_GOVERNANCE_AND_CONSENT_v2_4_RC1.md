# OSLT Restricted Data Governance and Consent v2.4 RC1

## Architectural rule
OSLT uses a federated evidence architecture. Controlled NHS, ONS, DfE and other sensitive person-level data remain inside the data owner's approved TRE/SDE or equivalent secure setting. OSLT takes approved code/specifications to the data and receives permitted disclosure-checked results.

## Four stores
1. **OPEN:** public documents/APIs/aggregates.
2. **LICENSED/SAFEGUARDED:** provider-controlled research data under licence.
3. **PARTICIPANT SECURE:** explicitly consented primary data and donated digital histories.
4. **TRE/SDE:** controlled administrative/health/education microdata; no raw central export.

## Participant private data
Emails, messages, browsing/search histories, private platform data and medical records must never be acquired by bypassing access controls. Collection is only through an approved study with explicit scope, consent/authorisation, minimisation, third-party-content handling and secure storage.

## Children and vulnerable participants
Any primary research involving children or vulnerable participants requires institutionally approved ethics, safeguarding, capacity/assent/consent procedures and a clear risk-management protocol. OSLT documentation is not a substitute for REC/IRB/data-controller approval.

## Five-Safes alignment
For controlled data, record safe people, safe project/public benefit, safe setting, safe data and safe outputs.
